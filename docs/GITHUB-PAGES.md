# Публикация макета на GitHub Pages

Проект подготовлен для бесплатного размещения из публичного репозитория. Для сайта не нужны Node.js, сборка на GitHub, база данных или настройка сервера. Node.js используется только локально, если требуется заново подготовить папку публикации.

## 1. Создайте репозиторий

1. Войдите в GitHub и нажмите **+ → New repository**.
2. Назовите репозиторий, например `nozim-work-app`.
3. Выберите **Public**. На бесплатном GitHub Pages репозиторий должен быть публичным.
4. Включите **Add a README file**, чтобы сразу появилась ветка `main`.
5. Нажмите **Create repository**.

## 2. Загрузите подготовленный сайт

Готовые файлы находятся в `dist/`, а их архив — в `releases/github-pages.zip`.

1. Откройте папку `dist/` в Finder. Или распакуйте архив и откройте полученную папку.
2. В репозитории выберите **Add file → Upload files**.
3. Перетащите **содержимое** папки: `index.html`, папки `css`, `js`, `assets` и файл `.nojekyll`. Не перетаскивайте саму папку `dist`: `index.html` должен оказаться в корне репозитория. ZIP сам по себе GitHub не распакует.
4. На macOS скрытые файлы показывает сочетание **⌘⇧.**. Файл `.folio-generated` служебный; его загружать не нужно.
5. Сохраните загрузку в `main` через **Commit changes**.

Если `.nojekyll` не удалось загрузить: **Add file → Create new file**, имя `.nojekyll`, содержимое можно оставить пустым или написать `Static HTML site`, затем сохраните в `main`.

Ожидаемая структура на вкладке Code:

```text
index.html
.nojekyll
css/
js/
assets/
README.md        ← README, созданный GitHub, может остаться
```

## 3. Включите GitHub Pages

1. Откройте **Settings → Pages**.
2. В разделе **Build and deployment** установите:
   - **Source:** `Deploy from a branch`.
   - **Branch:** `main`.
   - **Folder:** `/(root)`.
3. Нажмите **Save**.
4. Дождитесь завершения публикации. Статус доступен на вкладке **Actions**, а ссылка появится в **Settings → Pages** — кнопка **Visit site**.
5. Если доступно, оставьте **Enforce HTTPS** включённым.

GitHub Pages не требует вводить build command: загружены уже готовые файлы. Не выбирайте `/docs` — эта папка у нас содержит документацию, а не сайт.

## 4. Откройте и отправьте клиенту

Адрес будет таким (замените USERNAME своим логином и имя репозитория своим):

```text
https://USERNAME.github.io/nozim-work-app/
```

Для явного показа конкретного экрана:

```text
https://USERNAME.github.io/nozim-work-app/#welcome
https://USERNAME.github.io/nozim-work-app/#home
https://USERNAME.github.io/nozim-work-app/#work/house
```

Слеш перед `#` сохраняйте. Не используйте `/work/house` вместо `#work/house`. По обычному адресу новый посетитель увидит приветствие; сохранённая демо-сессия открывает главную. Ссылка `#welcome` всегда открывает приветствие.

Проверьте сайт в приватном окне: приветствие, создание аккаунта/вход, фото, галерея, настройки и переключение языка. Демо-код: **123456**.

## 5. Как обновлять макет

1. Измените исходные файлы проекта.
2. Запустите `npm run build` из папки проекта. Установка пакетов не нужна.
3. Загрузите актуальные файлы из `dist/` на место прежних в корне `main` и сохраните изменения. Если исходные файлы были удалены или переименованы, удалите прежние файлы и в репозитории.
4. Дождитесь новой публикации во вкладке Actions. Старый ZIP автоматически не обновляется — для обновлений используйте свежую папку `dist/`.

Настройки Pages повторно менять не нужно. Если браузер показывает старую версию, сделайте жёсткую перезагрузку страницы.

## Что именно будет публичным

Публикуется интерактивный демонстрационный макет. Вход Google/Apple и код по почте имитируются; писем нет. Профиль, работы, отзывы и фотографии являются демо-данными. Изменения сохраняются в localStorage отдельно у каждого посетителя и не передаются клиенту при отправке ссылки. Фотографии, добавленные на localhost, автоматически на GitHub не попадут. Чтобы изменить общий исходный профиль для всех, измените `js/data.js` и соответствующие локальные материалы, подготовьте и загрузите новую версию. У посетителей с ранее сохранёнными данными seed не заменит localStorage: для просмотра новой демо-версии используйте приватное окно или «Восстановить демо».

## Если что-то не работает

- **404:** проверьте, что `index.html` находится в корне `main`, Pages использует `main / (root)`, публикация прошла успешно и адрес содержит имя репозитория.
- **Нет стилей/картинок:** проверьте, что `css`, `js`, `assets` загружены целиком и сохранили названия и вложенность.
- **Не появляется ссылка:** откройте Actions и проверьте результат `pages build and deployment`; для публикации нужен подтверждённый email аккаунта и разрешённые Actions в репозитории.

Официальные инструкции: [настройка источника GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [загрузка файлов через GitHub](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).
