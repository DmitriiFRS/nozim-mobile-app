# План реализации мобильного портфолио

Дата: 10 октября 2026 года. Рабочее название: Folio, можно заменить после согласования бренда.

## Цель и направление

Подготовить клиенту наглядный мобильный макет, позволяющий пройти путь от создания профиля до просмотра опубликованной работы. Основная аудитория: строители и специалисты по ремонту. Модель контента и язык интерфейса должны подходить и другим профессиям.

Главный визуальный ориентир: `assets/reference/main-reference.png`. Тёмный графитовый фон, большая фотографическая обложка, круглый портрет, читаемые контакты, округлая навигация. Стеклянный материал применяется к управлению; текст и фотографии остаются читаемыми. Ширина основного мобильного макета: 430 px. На узких экранах интерфейс занимает всю ширину. На компьютере предусмотрена презентационная оболочка.

Стек: HTML + CSS + JavaScript. Нативная реализация без сборщика и тяжёлого фреймворка. Плавность эффектов ограничена короткой обратной связью; постоянные анимации не нужны.

## Карта экранов

| Экран | Маршрут макета | Содержание | Основной сценарий |
| --- | --- | --- | --- |
| Главный | `#home` | Обложка, аватар, имя, профессия, город, контакты, настраиваемые вкладки-ссылки | Перейти на отдельный экран выбранного раздела |
| Мои работы | `#works` | Сетка работ, фильтры категорий, добавление | Найти релевантный проект |
| Карточка работы | `#work/:id` | Фото, описание, роль, место, год, результат | Понять задачу и вклад специалиста |
| О себе | `#about` | Опыт, описание, услуги и навыки | Узнать компетенции |
| Создание профиля | `#create-profile` | Имя, профессия, город, фото, описание, услуги, контакты | Заполнить или изменить профиль |
| Создание работы | `#create-work` | Название, категория, описание, фото, роль и результат | Добавить проект |
| Сертификаты | `#certificates` | Только опубликованные записи | Посмотреть образование и квалификацию |
| Вкладки профиля | `#edit-tabs` | Названия, порядок, видимость и собственные текстовые разделы | Настроить структуру портфолио |
| Собственная вкладка | `#section/:tabId` | Заголовок, текст пользователя, кнопка возврата | Просмотреть содержание отдельного раздела |

Для реального приложения нужно разделить гостевой просмотр и управление владельцем: кнопки создания и изменения доступны владельцу. В клиентском макете все сценарии открыты для демонстрации.

## Правило сертификатов

Условие видимости: вкладка включена владельцем и `certificates.some(certificate => certificate.published === true)`. Условие привязано к типу вкладки, а не к её редактируемому названию.

При нуле опубликованных записей скрывается вкладка профиля и ссылка презентационной навигации. Черновик не включает раздел. При прямом открытии экрана сертификатов без записей показывается объяснение. Удаление или снятие публикации последней записи скрывает раздел. В макете предусмотрен переключатель демо-записи для проверки обоих состояний.

Обновление 11 октября 2026 с уточнением пользователя: блок «Избранные работы» удалён. Все вкладки главной ведут на отдельные экраны, контент разделов на главной не отображается. На экране «Работы» показывается полный список. Добавлен редактор вкладок с локальным сохранением, переименованием, изменением порядка, скрытием и созданием собственных текстовых разделов. Как минимум одна вкладка, не зависящая от сертификатов, остаётся видимой. Существующие сохранённые профили получают стандартные вкладки без потери данных. Старые адреса `#home/:tabId` перенаправляются на отдельные экраны.

Сертификаты публикуются самим специалистом. Подтверждение подлинности является отдельным будущим процессом и не имитируется значком проверки.

## Универсальность для профессий

- Профессия вводится свободно, список не ограничивает пользователя строительством.
- Категория выбирается из подсказок или вводится вручную.
- Основные поля работы: задача, описание, роль и результат. Метраж, смета и строительные этапы не обязательны.
- Для фотографа подходят съёмки; для дизайнера проекты; для строителя объекты. Модель Work остаётся общей.
- Расширения по профессиям добавляются как необязательные поля после выбора специализации.
- Контакты, город, навыки и сертификаты одинаково работают для всех профессий.

## Критерии готовности макета

- Все заявленные экраны доступны и переходы работают.
- На ширинах 320–430 px нет горизонтального переполнения.
- Главный экран сохраняет композицию исходного референса.
- Эффект кнопок отделён от логики приложения, поддерживает очистку.
- Формы объясняют обязательность полей и показывают ошибки.
- После перезагрузки видны сохранённые локальные данные.
- Раздел сертификатов отсутствует при нуле опубликованных записей.
- Демо-контент и локальный характер публикации объяснены пользователю.
- Синтаксис JS и ключевые сценарии проверены; подробности в `docs/QA.md`.

Нижнее меню согласовано и уточнено: «Главная», центральная кнопка создания работы «+», «Настройки». Дублирующий раздел «Публикации» удалён. Работы доступны через раздел профиля. Редакторы скрывают панель; создание работы запоминает экран возврата, включая перезагрузку формы.

Настройки: независимые редакторы личных данных и контактов, список сертификатов с созданием и редактированием, публикацией и удалением, загрузкой фото. Русский и английский интерфейс сохраняются отдельной настройкой; локализация статических частей HTML-шаблонов не затрагивает интерполированные пользовательские данные. Меню и диалоги оболочки локализуются из исходного текста.

Категории хранятся отдельно как id/name; существующие профили получают их из текущих работ без потери контента. Работы связаны categoryId, поле category сохраняется для совместимости. Категории управляются отдельным редактором с валидацией уникальности; новые названия из формы работы добавляются автоматически. Фильтры работают по id. Описания карточек ограничены тремя строками; исходный текст не сокращается в данных.

Добавлен маршрут `#edit-work/:id`, использующий общую форму работы. Сохранение по id заменяет запись на месте, сохраняет дополнительные фотографии и добавляет новую категорию при вводе. Удаление по id после подтверждения возвращает в список; недоступные id показывают экран отсутствующей работы.

Галерея реализована нативным горизонтальным scroll-snap с отдельным контроллером js/work-gallery.js. Стрелки, миниатюры и клавиатура меняют позицию; скролл обновляет описание, счётчик и доступность стрелок. ResizeObserver сохраняет активную фотографию при смене ширины, контроллер очищается при смене маршрута. Модель photos: id/src/caption; image/images восстанавливаются как совместимые производные значения. Старые портфолио мигрируют без потери изображений. Редактор использует общий черновик, сохраняет текст при добавлении/перестановке фото и блокирует сохранение на время загрузки файлов.

Rich text реализован в js/rich-text.js: contenteditable, панель команд, ссылки с проверкой схемы, сохранение выделения, очистка HTML при вставке и сохранении. descriptionHtml используется в верхнем блоке «О проекте», description содержит plain text для карточек. Старые описания автоматически отображаются как абзацы. Контроллер очищается при смене экрана.
