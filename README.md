# Folio: мобильное портфолио

Локальный интерактивный макет для показа клиенту. Чистые HTML, CSS и JavaScript, без зависимостей, сборки и регистрации. Работает для строительства, архитектуры, дизайна, фотографии и других профессий.

## Запуск

```sh
npm run dev
```

Откройте http://localhost:4173. Требуется Node.js. Установка пакетов не нужна. Можно открыть `index.html` напрямую, но локальный HTTP-сервер предпочтителен для стабильной работы хранилища и копирования ссылок.

На компьютере рядом с мобильным макетом есть навигация по экранам. На телефоне отображается само приложение. Для проверки ширин используйте режим устройства в браузере: 320, 375, 390 и 430 px.

## Что можно показать

- Главный экран с обложкой, аватаром, контактами и настраиваемыми вкладками-ссылками. Контент разделов на главной не отображается: «Работы», «О себе», «Сертификаты» и собственные вкладки открывают отдельные экраны с кнопкой возврата.
- Нижнее меню: «Главная», центральная кнопка «+» (создание работы), «Настройки». Панель скрыта в редакторах; отмена новой работы возвращает на исходный экран.
- Настройки (`#settings`): личные данные, контакты, сертификаты и язык интерфейса (русский / English). Каждый пункт редактируется на отдельном экране; есть сохранение и отмена. Язык сохраняется после перезагрузки, тексты портфолио не переводятся.
- Мои работы: список, фильтры по категории, переход к карточке.
- Карточка работы: описание проекта с rich text, галерея с индивидуальными подписями и результат.
- О себе: описание, опыт, услуги, переход к редактированию.
- Создание профиля: изменение демо-данных, загрузка аватара и обложки, контакты, необязательный сертификат.
- Создание работы: универсальные поля, своя категория, загрузка фото и локальная публикация.
- Сертификаты: пункт навигации появляется только при наличии хотя бы одного опубликованного сертификата.
- Вкладки профиля: переименование, изменение порядка, скрытие и добавление собственных текстовых разделов. Открывается через «Настроить вкладки» под вкладками или меню профиля. Настройки сохраняются после перезагрузки; отмена не применяет изменения.

Кнопка «Добавить демо-сертификат» слева проверяет условную видимость. На телефоне эта функция находится в меню с тремя точками на обложке. Свою запись можно создать в форме профиля, заполнив название сертификата и включив публикацию. Неопубликованные записи не показываются посетителю. Скрытый экран по прямой ссылке показывает объяснение вместо списка.

## Стеклянные кнопки

```js
// Функция доступна после подключения js/glass-buttons.js.
const cleanup = initGlassButtons(document, { intensity: 1 });
// Перед заменой экрана:
cleanup();
// После появления новых элементов:
const nextCleanup = initGlassButtons(document);
```

Добавляйте `class="glass-button" data-glass` к кнопке или ссылке. CSS рисует материал, JS перемещает световой блик и даёт обратную связь на нажатие. Функция возвращает очистку обработчиков и анимаций. Поддержаны клавиатура, touch, reduced motion, reduced transparency и непрозрачный fallback без blur. Это самостоятельная веб-аппроксимация, а не официальный Apple Liquid Glass.

## Границы макета

Данные сохраняются только в `localStorage` этого браузера. Серверной публикации, входа, проверки сертификатов и отправки сообщений нет. Демонстрационные контакты пустые; нажатие объясняет, где добавить свои. Фотографии и тексты являются примерами. Загрузка изображений ограничена 2 МБ на файл; при переполнении хранилища форма сообщает об ошибке и не меняет данные. Ссылка «Поделиться» ведёт на текущий адрес макета, включая адрес GitHub Pages после размещения. Она не передаёт изменения из localStorage другим посетителям.

«Восстановить демо» требует подтверждения и заменяет локальные пользовательские данные. Для чистой демонстрации можно использовать отдельное окно браузера.

Проверка синтаксиса: `npm run check`.

Редактирование: `#personal-data`, `#contacts-edit`, `#certificates-edit`, `#certificate-edit/new` или `#certificate-edit/:id`, `#language`. Сертификаты поддерживают несколько записей, загрузку фото, изменение, публикацию/скрытие и удаление с подтверждением. Фото сохраняются локально (до 2 МБ на файл).

Категории работ: `#categories-edit` открывается через «Управлять категориями» на экране «Работы». Можно добавлять, переименовывать и удалять категории. Изменения применяются после сохранения; удаление категории сохраняет работы без категории. В форме работы доступны свои категории и ввод новой. Описание карточки ограничено тремя строками, полный текст доступен при открытии работы.

Редактировать работу: откройте работу и нажмите карандаш рядом с «Поделиться». Маршрут `#edit-work/:id` открывает заполненную форму. Сохранение обновляет запись без дублирования, замена основного фото сохраняет остальные фотографии галереи. Удаление находится внизу редактора и требует подтверждения.

Галерея работы: свайп, стрелки, миниатюры, клавиши ←/→ и Home/End. У каждого фото отдельное описание. В редакторе доступно до восьми фотографий (до 2 МБ на файл), собственные подписи, замена, удаление и изменение порядка. Первая фотография становится обложкой. Галерея сохраняется локально; при переполнении хранилища форма сообщает об ошибке. Фотографии сериализуются однократно в photos, прежние image/images восстанавливаются в памяти для совместимости. Управление галереей вынесено в `js/work-gallery.js`, функция `initWorkGallery()` возвращает очистку обработчиков.

Описание «О проекте» всегда отображается перед галереей. В редакторе доступны жирный, курсив, маркированный и нумерованный списки, ссылки и удаление форматирования. Описание сохраняется как очищенный descriptionHtml и текстовый description для превью карточек. Вставляемый HTML очищается от скриптов, небезопасных ссылок и произвольных атрибутов.

## Публикация на GitHub Pages

Проект готов к размещению в подпапке репозитория: относительные пути к ресурсам, hash-маршрутизация, локальные фотографии и шрифты. `.nojekyll` отключает обработку Jekyll.

```sh
npm run build
```

Команда проверяет синтаксис и создаёт `dist/` с файлами сайта. Установка пакетов не требуется. `dist/` генерируется заново; изменения вносите в исходные файлы. Сервер разработки и внутренняя документация в эту папку не попадают.

Пошаговая инструкция: [docs/GITHUB-PAGES.md](docs/GITHUB-PAGES.md). Подготовленный архив: `releases/github-pages.zip`.
